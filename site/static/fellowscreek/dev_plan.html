Core game mechanics
Turn-based play for four asymmetric roles
The game is turn-based with four players (Farmer, Ecologist, Road Manager, Land Manager). Player activities are divided into two categories that determine when they may be performed:
Major activities
High-impact actions that change the state of the watershed — e.g. removing a log, building a well. Permitted only during the active player's turn.
Minor activities
Low-impact upkeep and observation — e.g. repairing a road, watering plants, measuring water quality. Permitted at any time, on or off turn.
Square-tile game board with terrain & state
The board is built from square tiles, each with an assigned ID. Every tile carries a defined terrain type (forest, field, town, creek, etc.) and a set of potential states (thriving, degraded, flooded, dry, etc.). Tile state is the primary surface through which the water simulation, wood logic, and role actions express their effects — making the tile/state model the shared data structure underlying both gameplay and analytics.
Retro pixel-art presentation with explorable world
Visuals use pixelated artwork in the style of a retro arcade game, in the vein of Japan Rural Adventure (Apple Arcade). Characters walk around the world and see only part of the environment at a time (a viewport, not the full board), and can open a full overview map from the main menu. This framing informs the isometric renderer, camera/viewport handling, and the menu-accessed map view.
Recommended tech stack
Frontend
React + TypeScript
Component-based UI maps cleanly to role dashboards. TS catches bugs early in a complex multiplayer state machine. i18n-ready for Spanish.
Game rendering
PixiJS
WebGL-based 2D renderer ideal for the square-tile board, pixel-art retro presentation, animated water/tile states, and a per-character viewport with real-time updates without heavy 3D overhead.
Multiplayer
Colyseus
Purpose-built multiplayer game server with room management and authoritative state sync. Stable across language clients (critical for Spanish launch).
Backend
Node.js + Express
Native Colyseus match. Fast iteration and easily deployable on Fly.io for low-latency WebSocket connections.
Database
Supabase (Postgres)
Player sessions, game state snapshots, analytics. Built-in auth and locale field to support language preferences post-launch.
Localization
react-i18next
Industry-standard i18n library for React. Handles Spanish text expansion (20–30% longer), dynamic variables, and runtime language toggle.
Asset pipeline
Aseprite + TexturePacker
Aseprite for retro pixel-art tile and character creation (referencing the Japan Rural Adventure aesthetic). TexturePacker bundles sprites into atlases. Plan for text-free art assets to simplify Spanish localization.
Hosting
Vercel + Fly.io
Vercel for zero-config frontend deploys with instant language-toggle support. Fly.io for the persistent WebSocket game server with auto-scaling.

Key risks & mitigations
High
Research-to-code translation (new Phase 1 risk)
The science team must produce a concrete "logic map" document — not just research notes — before Phase 2 begins. Engineer should attend at least one expert interview to ask implementation-specific questions.
High
Water simulation complexity
Use a tile-based flow approximation rather than true fluid dynamics. The Phase 1 logic map should define the minimum viable physics rules — scope these tightly before Phase 3 begins.
High
Multiplayer state conflicts
Authoritative server model via Colyseus from day one. Clients send intents, server owns truth. Verify this holds across English and Spanish clients during Spanish QA.
Med
Spanish text expansion breaking UI
Build all UI components with flexible-width containers from Phase 2 onward. Avoid fixed-width text buttons. Use react-i18next from the start so the toggle is a post-launch config change, not a rewrite.
Med
Role balance (4 asymmetric players)
Build an admin panel to adjust budget numbers without code deploys. Each role's unique special skill (Farmer pond, Ecologist anchoring, Road Mgr deflector, Land Mgr floodplain) widens the balancing surface — expose skill costs/effects in the panel too. Use Phase 4 and Phase 6 workshop data to calibrate in two rounds before launch.
Low
Post-launch server costs
~$170/month. Fly.io auto-scales down during off-hours. Budget a 6-month hosting reserve (~$1,020) into the Scope 2 infrastructure allocation.
Key decisions to make before Phase 2
i18n architecture — decide now
Even though Spanish is post-launch, baking react-i18next into the component architecture in Phase 2 costs almost nothing. Retrofitting it after launch could require touching every UI component.
Text-free art assets
Direct the 2D artist to avoid embedded English text in tiles (signs, labels, map overlays). This eliminates an entire Spanish localization cost category and speeds up the post-launch timeline.
Classroom vs. public audience
Affects auth model and session management. A facilitated workshop needs a simple room-code join flow; a public release needs accounts, persistence, and content moderation.
Analytics schema for SMRCD
Define which player choices and outcomes to log from day one. Supabase can capture this cheaply, but only if the schema is designed upfront — retrofitting analytics is costly.
